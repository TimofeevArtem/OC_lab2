# Лабораторная работа №2

## Создание процессов и взаимодействие через каналы

**ФИО:** Тимофеев Артём Павлович

**Группа:** 201

**Вариант:** 14

### Цель работы

Приобрести практические навыки создания дочерних процессов в операционной системе Windows, организации обмена данными между процессами через неименованные каналы(pipe), перенаправления стандартных потоков ввода и вывода, создания потоков и управления системными ресурсами с использованием WinAPI.

### Постановка задачи

Разработать программу на языке Си с использованием WinAPI. Родительский процесс создаёт два дочерних процесса и организует передачу данных между ними через три неименованных канала. Вводимый пользователем текст передаётся первому дочернему процессу, который преобразует английские буквы в нижний регистр. Результат передаётся второму дочернему процессу, который удаляет повторяющиеся подряд пробелы. Итоговый текст возвращается родительскому процессу и выводится на экран.

Для обмена данными используются три канала: первый передаёт данные от родительского процесса первому ребёнку, второй — от первого ребёнка второму, третий — от второго ребёнка родительскому процессу. Родительский процесс должен обрабатывать ошибки системных вызовов, закрывать ненужные дескрипторы и дожидаться завершения дочерних процессов и потока чтения результата.

### Алгоритм решения

1. Родительский процесс объявляет дескрипторы трёх каналов, дескрипторы процессов и дескрипторы потока чтения. Для хранения информации о дочерних процессах используются структуры `PROCESS_INFORMATION`, а для настройки стандартных потоков — `STARTUPINFOA`.

2. С помощью структуры `SECURITY_ATTRIBUTES` задаются атрибуты безопасности каналов. Поле `bInheritHandle` устанавливается в `TRUE`, чтобы разрешить наследование дескрипторов дочерними процессами. Три неименованных канала создаются с помощью функции `CreatePipe`.

3. С помощью `SetHandleInformation` наследование дескрипторов сначала отключается, а затем включается только для тех дескрипторов, которые необходимы соответствующему дочернему процессу. Это позволяет ограничить набор наследуемых дескрипторов.

4. Для запуска первого дочернего процесса настраивается структура `STARTUPINFOA`. Устанавливается флаг `STARTF_USESTDHANDLES`, указывающий Windows использовать заданные стандартные потоки. Стандартный ввод первого ребёнка связывается с читающим концом первого канала `p1_read`, а стандартные вывод и поток ошибок — с записывающим концом второго канала `p2_write`. Затем с помощью `CreateProcess` запускается программа `child1.exe`.

5. После создания первого ребёнка родитель отключает наследование дескрипторов, которые больше не должны передаваться новым процессам. Для второго дочернего процесса настраивается перенаправление стандартного ввода на читающий конец второго канала `p2_read`, а стандартных вывода и потока ошибок — на записывающий конец третьего канала `p3_write`. Второй ребёнок запускается с помощью `CreateProcess` и выполняет программу `child2.exe`.

6. После запуска обоих дочерних процессов родитель закрывает собственные копии ненужных дескрипторов каналов. Это необходимо для корректного завершения передачи данных и получения признака конца потока, когда все записывающие дескрипторы соответствующего канала закрыты.

7. Для чтения итогового результата создаётся отдельный поток с помощью `CreateThread`. Функция `ReadOutput` получает дескриптор читающего конца третьего канала через параметр `LPVOID`, преобразует его к типу `HANDLE` и последовательно считывает данные с помощью `ReadFile`. Каждый полученный символ выводится на экран функциями `putchar` и `fflush`.

8. Основной поток родительского процесса считывает символы с клавиатуры с помощью `getchar`. Каждый символ передаётся первому дочернему процессу через первый канал с помощью `WriteFile`. Запись выполняется по одному байту. При ошибке записи или неожиданном количестве записанных байтов выводится сообщение об ошибке.

9. После завершения ввода родитель закрывает записывающий дескриптор первого канала `p1_write`. Это позволяет первому ребёнку получить конец входного потока после обработки всех переданных данных. После закрытия входного потока первый ребёнок завершает передачу данных второму, а второй ребёнок после обработки полученных данных закрывает свой выходной поток.

10. Родитель ожидает завершения первого дочернего процесса, второго дочернего процесса и потока чтения результата с помощью `WaitForSingleObject` с параметром `INFINITE`. После завершения работы закрываются дескрипторы потока, каналов и обоих дочерних процессов.

### Используемые программы и организация взаимодействия

В решении используются три исполняемых файла: `parent.exe`, `child1.exe` и `child2.exe`. Родительская программа запускает два дочерних процесса с помощью `CreateProcess`. Первый ребёнок преобразует английские буквы в нижний регистр, а второй удаляет повторяющиеся подряд пробелы.

Для передачи данных используются три неименованных канала:

- **Первый канал (`p1`)** — передача исходного текста от родительского процесса первому ребёнку.
- **Второй канал (`p2`)** — передача текста после преобразования регистра от первого ребёнка второму.
- **Третий канал (`p3`)** — передача итогового текста от второго ребёнка родительскому процессу.

Таким образом, последовательность обработки данных выглядит следующим образом:

`Родитель → child1.exe → child2.exe → Родитель`

Родительский процесс содержит основной поток, который читает пользовательский ввод и передаёт его первому ребёнку, а также дополнительный поток `ReadOutput`, который получает итоговые данные из третьего канала и выводит их на экран. Каждый дочерний процесс имеет собственный основной поток выполнения.

### Ввод и вывод программы

**Ввод:** произвольный текст, вводимый пользователем в консоли. Символы передаются первому дочернему процессу по мере чтения. Завершение ввода выполняется способом, предусмотренным используемой консолью и средой запуска.

**Обработка:** первый ребёнок переводит английские буквы в нижний регистр. Второй ребёнок удаляет повторяющиеся подряд пробелы, оставляя один пробел из каждой последовательности. Другие символы сохраняются.

**Вывод:** обработанный текст отображается в консоли родительского процесса. Передача данных осуществляется через три неименованных канала, а чтение результата выполняется отдельным потоком.

### Пример работы

Ввод:
```text
Hello     WORLD!
Это  тест.
```

Ожидаемый вывод:
```text
hello world!
Это  тест.
```

В первом дочернем процессе текст преобразуется к нижнему регистру. Во втором процессе последовательности из нескольких пробелов заменяются одним пробелом. Итоговые строки выводятся родительским процессом.

### Обработка ошибок и управление ресурсами

В программе проверяются результаты вызовов `CreatePipe`, `SetHandleInformation`, `CreateProcess`, `CreateThread` и `WriteFile`. При обнаружении ошибки выводится сообщение с кодом, полученным через `GetLastError`.

После использования дескрипторы каналов закрываются с помощью `CloseHandle`. Родительский процесс ожидает завершения дочерних процессов и потока чтения, прежде чем завершить работу. Это позволяет избежать преждевременного завершения родительской программы, пока дочерние процессы ещё обрабатывают данные или итоговый результат ещё не прочитан.

### Вывод

В ходе лабораторной работы разработана программа на языке Си с использованием WinAPI для взаимодействия родительского и двух дочерних процессов посредством трёх неименованных каналов. Реализованы создание каналов с помощью `CreatePipe`, запуск дочерних процессов с помощью `CreateProcess`, перенаправление стандартных потоков через `STARTUPINFO` и `STARTF_USESTDHANDLES`, а также управление наследованием дескрипторов посредством `SetHandleInformation`.

Организована последовательная обработка текста: первый дочерний процесс преобразует английские буквы в нижний регистр, второй удаляет повторяющиеся подряд пробелы. Для чтения итогового результата создан отдельный поток с помощью `CreateThread`, который получает данные из третьего канала и выводит их на экран.

В программе используются функции `ReadFile` и `WriteFile` для передачи данных, `WaitForSingleObject` для ожидания завершения процессов и потока, а также `CloseHandle` для освобождения системных ресурсов. В результате освоены основные принципы создания процессов, межпроцессного взаимодействия через неименованные каналы, перенаправления стандартных потоков и синхронизации выполнения в Windows.
